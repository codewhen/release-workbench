# Workflow configuration reference

The [JSON Schema](../src/release_workbench/schema.json) is the complete version 1 contract. Unknown properties are errors. YAML must contain plain JSON-compatible values: no aliases, custom tags or implicit timestamp objects. Quote date values. The editor preserves ordinary comments and named step comments where possible; it may normalize indentation.

## Workflow fields

| Field | Purpose / default |
|---|---|
| `version` | Required; `1` |
| `name`, `description` | Human-readable workflow identity and instructions |
| `concurrency` | Maximum simultaneous jobs; default `4`, range 1–64 |
| `steps` | Nodes, identified by stable lowercase IDs |
| `inputs` | Named typed input definitions |
| `env` | Additional process environment values |
| `secret_env` | Names of launching-environment variables to mask in logs/state |
| `profiles` | Map profile names to step ID arrays; dependencies are included |
| `report_paths` | Workspace directories whose reports may be opened locally |
| `source_paths` | Additional file glob patterns included in the source fingerprint |
| `detect` | Read-only candidate-discovery command hook and timeout |

## Step fields

Required fields are `id`, `name` and `kind` (`command` or `manual`). The browser generates stable IDs. Rename the human name freely; dependencies refer to the ID.

| Field | Purpose / default |
|---|---|
| `commands` | Ordered commands within one job |
| `platform_commands` | `macos`, `windows`, `linux` command overrides; an unavailable platform blocks the job |
| `cwd` | Working directory under the workspace; default `.` |
| `needs` | All prerequisite step IDs; default none |
| `requires_inputs` | Inputs that must have valid values before starting |
| `resources` | Exclusive named locks, e.g. `device:${input.serial}` |
| `env`, `secret_env` | Step environment values and additional secret names |
| `mode` | `background` (default) or `interactive`; interactive reserves `desktop` |
| `exclusive` | Drain all other jobs and run alone; default false |
| `enabled` | Default true; false does not satisfy prerequisites |
| `required` | Default true; included in final approval validation |
| `approval` | Manual final decision requiring all other required non-approval steps as ancestors |
| `timeout` | Entire job budget in seconds, including ordered commands; default 3600 |
| `expected_seconds` | First-run estimate; default 60; later successful medians improve estimates |
| `progress` | Regex parser configuration, described below |
| `reports` | Fresh report glob patterns; collected paths and SHA256 values |
| `outputs` | JSON output bindings to workflow inputs |
| `position` | Optional canvas `x`/`y`; never affects execution order |

Manual gates contain instructions and dependencies, not commands. Connect multiple final approval gates explicitly if publication evidence follows a release decision; the engine never submits anything automatically.

## Commands and values

```yaml
commands:
  - argv: ['${python}', 'scripts/test.py', '--device', '${input.serial}']
  - shell: bash
    script: 'printf "Checks complete\n"'
env:
  SERVICE_TOKEN: '${env.SERVICE_TOKEN}'
secret_env: [SERVICE_TOKEN]
```

`argv` launches directly without a shell. Shell commands require both `shell` and `script`; supported shells are bash, sh, powershell and cmd. Shell scripts cannot interpolate `${input.*}`: pass user inputs as direct arguments or environment values. Runtime variables include `${python}`, `${workspace}`, `${platform}`, `${input.NAME}` and `${env.NAME}`. Missing values block preparation. Paths used for working directories, reports and output collection must stay inside the workspace, including resolved symlinks.

Secrets belong in the terminal/CI environment, never the YAML file or browser inputs. `secret_env` masks configured secret values before saved logs and state; it is not a general secret scanner and cannot sanitize arbitrary nested files generated by your commands. Treat reports as private until reviewed.

## Inputs and detection

```yaml
inputs:
  serial: {label: USB device, type: usb_serial}
  host: {label: LAN address, type: ipv4}
  pid: {label: Release process ID, type: pid}
  target: {label: Target, type: choice, options: [macos, windows], default: macos}
detect:
  commands:
    - argv: ['${python}', 'scripts/detect.py']
  timeout: 30
```

Types: string, integer, boolean, choice, ipv4, usb_serial and pid. Definitions can specify default, options, required, string pattern and numeric minimum/maximum. Input detection prints one JSON object containing candidate arrays: `{"serial":[{"value":"USB_EXAMPLE","label":"Example phone"}],"warnings":[]}`. Add `automatic:false` to candidates that need explicit user selection. Hooks are configured commands; the runner does not contain application-specific detection code.

JSON output bindings configure `path` (glob), `key` (dot path into the JSON), and `input` (destination input name). `fresh` defaults true. For example, `{path: 'evidence/*/summary.json', key: desktop_pid, input: pid}` fills a process ID after preparation. Values must validate against the destination input type.

## Progress

A process can emit a line such as:

```text
::workbench::{"done":4,"total":10,"stage":"Testing component four"}
```

Alternatively configure `progress.pattern` and `mode`: `count` counts matching lines with a configured `total`; `groups` reads named `done` and `total` capture groups; `index` reads named `done` with configured `total`. `offset` adjusts captured indices. Percentages remain below 100 until the command finishes. Without events or parsers, progress/ETA uses a visibly labelled estimate. Execution reaching 100% is separate from passing the release gate.
