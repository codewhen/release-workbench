# Workbench manual

Build a flowchart, run local automation, and inspect what happened. This manual starts with a blank project and then explains every current card and setting.

## Choose your route

- **New to Workbench?** Begin with [installation](user/installation.md), then [your first workflow](user/first-workflow.md).
- **Need a particular operation?** Browse the [card reference](user/cards/index.md): 25 executable card types and three layout tools, each with screenshots and downloadable examples.
- **Confused about data or control flow?** Read [connections and values](user/values.md), [Start/Finish/Return](user/tutorials/completion.md), [functions](user/tutorials/functions.md) and [variables](user/tutorials/variables.md).
- **Already running work?** Read [running and evidence](user/running.md), [troubleshooting](user/troubleshooting.md) and [storage](user/storage.md).
- **Contributing code?** The [Developer guide](developer/index.md) explains internals, tests and packaging separately.

## Read and practice

Instructions use the actual browser labels. Screenshots come from disposable projects running the real application; they contain synthetic examples, not personal workflows. Select a screenshot to enlarge it, or use Enter when it has keyboard focus.

Every card page links a complete YAML workflow. Download it into a separate project directory and follow its prerequisites before running. Examples that write files use an `output/` folder within that disposable project. Review commands before running them: Workbench executes trusted local automation with your user permissions.

The site works locally under **Documentation** in the application, including search without an internet connection. Markdown is also readable in the repository. A GitHub Pages build is prepared separately; a prepared deployment workflow does not mean the website has been published.
